# Copilot-Assisted DAX Development Notes

## Project: BrewMetrics BI

This file documents how GitHub Copilot was used during the development of the DAX measures for the BrewMetrics BI project.

---

## 1. Total Sales

### Purpose

Calculate the total sales generated by all transactions.

### Copilot Suggestion

Copilot suggested using the `SUM()` function on the `sales_amount` column from the `Fact_Sales` table.

### Final Measure

```DAX
Total Sales =
SUM(Fact_Sales[sales_amount])
```

### My Changes

The suggested approach was directly usable. No major correction was required.

### Reason

`Fact_Sales[sales_amount]` contains the transaction-level sales values, so summing the column provides the total sales.

---

## 2. Month-over-Month Growth %

### Purpose

Measure the percentage change in sales compared with the previous month.

### Copilot Suggestion

Copilot suggested calculating the previous month's sales using `CALCULATE()` and `DATEADD()`, followed by calculating the percentage difference.

### Final Measures

```DAX
Previous Month Sales =
CALCULATE(
    [Total Sales],
    DATEADD(Dim_Date[Date], -1, MONTH)
)
```

```DAX
MoM Growth % =
DIVIDE(
    [Total Sales] - [Previous Month Sales],
    [Previous Month Sales]
)
```

### My Changes

I checked the suggested calculation against the date dimension and ensured that the calculation used `Dim_Date[Date]` rather than the transaction date directly from the fact table.

### Reason

The star schema uses `Dim_Date` as the date dimension. Using the date dimension allows the time-intelligence calculation to work through the relationship between `Dim_Date` and `Fact_Sales`.

---

## 3. Running Total Sales

### Purpose

Calculate cumulative sales over the selected period.

### Copilot Suggestion

Copilot suggested using `CALCULATE()` with a date filter so that all dates up to the current date are included.

### Final Measure

```DAX
Running Total Sales =
CALCULATE(
    [Total Sales],
    FILTER(
        ALLSELECTED(Dim_Date[Date]),
        Dim_Date[Date] <= MAX(Dim_Date[Date])
    )
)
```

### My Changes

I used `ALLSELECTED()` so that the running total respects the user's report selections while accumulating sales up to the current date.

### Reason

Using the selected date context makes the measure more suitable for an interactive Power BI dashboard containing slicers.

---

## 4. Product Sales Rank

### Purpose

Rank products according to their sales performance.

### Copilot Suggestion

Copilot suggested using `RANKX()` with the product column and the total sales measure.

### Final Measure

```DAX
Product Sales Rank =
RANKX(
    ALLSELECTED(Dim_Product[item]),
    [Total Sales],
    ,
    DESC,
    DENSE
)
```

### My Changes

I used `ALLSELECTED()` instead of removing all report filters so that the ranking can respond to the selections made by the dashboard user.

### Reason

This allows the ranking to remain meaningful when the dashboard is filtered by other dimensions.

---

## 5. Average Transaction Value

### Purpose

Calculate the average sales value per transaction.

### Copilot Suggestion

Copilot suggested dividing total sales by the number of transactions.

### Final Measure

```DAX
Average Transaction Value =
DIVIDE(
    [Total Sales],
    DISTINCTCOUNT(Fact_Sales[sale_id])
)
```

### My Changes

I used `DISTINCTCOUNT()` on `sale_id` rather than simply counting rows.

### Reason

Each transaction is identified by `sale_id`. Using `DISTINCTCOUNT()` makes the calculation explicitly based on unique transactions and avoids division by an incorrect row count if duplicate transaction IDs are present.

---

## Summary

GitHub Copilot was useful for generating the initial DAX structure and suggesting appropriate functions such as `SUM()`, `CALCULATE()`, `DATEADD()`, `FILTER()`, and `RANKX()`. However, the suggestions were reviewed against the project's star schema and dashboard requirements before being used.

The final measures were manually checked to ensure that they worked with the `Dim_Date`, `Dim_Product`, and `Fact_Sales` tables and behaved correctly when dashboard filters were applied.
